# Release-path security review · 2026-11-06

Scope: unreleased candidate packaging and deployment/rollback control flow on the development branch. This review does not certify the entire application, real host configuration, WAN reachability or Safari hardware. No user's computer or server was accessed.

| Finding | Evidence | Remediation | Remaining boundary |
|---|---|---|---|
| Candidate copied arbitrary working-directory content and only excluded the exact `.env` basename | Isolated fixture places `.env.production` and untracked local notes under server; old recursive directory copy would include them | Snapshot only clean HEAD-tracked allowlisted source; reject dirty tracked files, forbidden credential paths and symlinks; validate expected dist resources | Tracked files still need review; a clean Git tree is not a trust decision |
| Candidate could claim HEAD while packaging changed source or stale build output | Dirty fixture and mismatched build identity regression | Re-run check-build before archive; reject source changes during snapshot; per-file origin/size/mode/hash manifest | Build tools and source are assumed trusted; SHA-256 is not an independent signature |
| No bounded secret-content scan in candidate path | Tracked test token fixture is rejected without emitting value | Bounded rules for private keys, GitHub tokens, AWS access-key identifiers and OpenAI project keys | Does not detect all token types, encoded/split credentials or all personal data; manual review required |
| Rollback updated pointers before service readiness and lacked failure recovery | Isolated service restart/hello failure and shared-lock contention fixtures | Validate canonical release paths, serialize deploy/rollback with flock, check authorized WS hello, update reverse marker only after readiness; restore original target after failure | Actual systemd/TLS/disk failure and recovery remain external release gates |
| Process active state alone did not prove functioning signaling | Actual loopback WebSocket integration; wrong Origin cannot pass readiness | Bounded hello probe before deployment/rollback reports success; returned identity/token never logged | Does not prove WSS proxy, selected ICE pair, consent or file transfer |

Local focused validation: 13 tests passed across `tests/package-candidate.test.cjs` and `tests/deployment.test.cjs`. Packaging fixtures use isolated temporary Git repositories. Rollback fixtures adapt filesystem paths and omit the root guard in a temporary copy; production transition/trap logic runs with mocked service commands. The readiness helper uses the actual signaling service on loopback. No real `/opt`, `/etc`, systemd service, domain, certificate or production process was modified.

No source credential leak was observed or claimed in the actual repository. The packaging findings are proven boundary failures in constructed fixtures, not evidence that a historical distributed archive contained a real user's secret. The final integrated commit still requires full CI and an actual clean-source archive check.

## Follow-up deployment review

Two additional reproducible deployment defects were found after the first integration:

- The host lock was taken after dependency installation/tests/build. A second deployment in the same checkout could mutate node_modules or dist before waiting for the publication lock. It now locks before the first npm invocation and holds the lock through the complete transaction. An isolated production-script copy with another process holding the lock proves npm is never invoked; busy returns temporary-failure code 75 rather than claiming the active deployment is broken.
- Under umask 077, the old recursive copy plus removal of group/other writes left root-owned directories at 0700 and files at 0600, blocking the unprivileged Node/Nginx processes. Runtime tree directories are now explicitly 0755, ordinary files 0644 and previously executable files 0755. The test starts from genuinely restricted copied files and checks the final modes. Symlink/non-regular inputs are rejected before recursive ownership or permission changes, and a symlink regression verifies the outside target remains 0600. Local server .env files are not copied into the service tree.

The Node executable written into systemd is now its canonical filesystem path. Known ProtectHome/PrivateTmp-hidden locations are rejected with an actionable message; a temporary launcher pointing to the real system Node resolves successfully, while a temporary executable is rejected. This is path-policy validation, not a real systemd namespace test.

Additional transfer-authorization review: an OPFS writer was exposed to same-page recovery before its stored prefix hash and in-memory offset were prepared. The new regression fails on906a15c (advertised0 vs persisted16384B). Preparation now owns its sink locally, parks the original committed checkpoint on stale cancellation/disconnect, aborts corrupt/error paths, and rechecks identity/direct-path authorization across awaits. Six targeted cases cover disconnect, explicit cancellation, late restore, corruption, revoked identity and a new offer reusing an ID. No server file path or relay exception was introduced.

Receiver ownership and transfer-ID review: failed in-flight writes on an old peer now cancel the exact adopted state on its current owner; successful writes still advance its shared prefix, and late failures cannot cancel a fresh offer reusing an ID. A remote offer cannot alias an active local outgoing ID: three regressions cover native-writer cleanup, 64MiB fallback-budget recovery and normal distinct-ID bidirectional content. Both leak regressions fail on906a15c; four ownership and six preparation cases pass with the final integrated source.

Static publication follow-up: an isolated clone of9ad with synthetic, untracked client/.env.repro and private-notes.txt proved both files entered dist and changed the build revision under the old recursive copy. Candidate packaging already rejected unexpected dist files, but direct checkout deployment lacked that boundary. Build now uses an explicit public-input byte snapshot for hashing/copying, with file/ancestor symlink and special-file rejection; it works without Git metadata. The Nginx template independently rejects dotpaths while preserving.well-known. HTTPS regression places actual readable synthetic files under an isolated public root and checks404 even for encoded/nested requests. No actual repository credential or distributed-candidate leak was observed. This new boundary passed the full CI47 on code848d16c, including real Nginx fixtures and all139 Node tests. No real host or production acceptance is implied.
