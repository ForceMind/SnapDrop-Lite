# Zeydrop 浏览器本地断点（实验功能）

## 范围与用户操作

接收文件前主动选择“在本机保存断点”，数据仅写入该浏览器、该站点 Origin Private File System（OPFS）；不开启时沿用原来的 showSaveFilePicker/内存回退。中断后若刷新或关闭页面，双方需要新建邀请、重新建立非 relay WebRTC 路径、核对 DTLS 安全码。**发送者重新选择原文件**；接收者从收到的新邀请中主动确认匹配的本机断点，不能只凭名称自动恢复。恢复前本地读取并哈希检查点前缀，再由发送方对重新选择的文件计算同一偏移的 SHA-256；一致后才发送余下字节。全部文件必须再经过完整 SHA-256 才显示成功。

## 落盘边界及隐私

- 专用 Worker 用 FileSystemSyncAccessHandle 写入 OPFS（HTTPS 或 localhost），按约 1 MiB 更新持久化检查点；数据 flush **先于** JSON 清单的提交。崩溃可丢失最近不足 1 MiB 的进度，不能将未提交尾部当作有效内容，重新打开时必须截断到已保存 offset 并重新流式哈希。
- 明确保留最多 20 条记录，24 小时过期；用户可以在工作台“管理本机暂存文件”中手动删除或重新取得已完成且 SHA-256 校验通过的文件。完成文件也只在本机，用户点击保存后可删除副本。
- 本机暂存可能占用大量存储，受浏览器配额、隐私模式、清站点数据、OS 空间及存储驱逐影响，无法保证永远可恢复。站点同源脚本可以读取这些文件；不要在共享电脑上保留敏感内容。**文件数据、名称、哈希、偏移不进入 WSS 信令，也不上传服务器。**
- 界面上的匹配只是候选选择；不是授权或完整性凭证。使用非 relay selected ICE pair、双方重新人工核对安全码、用户接收确认、双方 prefix hash 和最终全量 hash 五层约束。失配不合并，要求重新传输或手动删除损坏的断点。
- OPFS 使用中的 exclusive lock 避免同一文件被多个 Writer 并发修改。硬件测试前不能保证 Safari/iOS 持久化和下载语义；浏览器不支持 Worker 同步访问句柄时不展示实验模式。
- 关闭浏览器不会保留发送方 File 句柄，也不会在服务端保存可恢复的会话 token。服务器重启后的信令身份和房间失效，必须创建新邀请；没有 TURN 文件中转。

## 自动化范围及待验收

`node tests/recovery-browser.cjs` 在 Chromium 使用真实 OPFS/Worker 验证先提交数据再提交元信息、意外刷新只恢复已确认前缀、后续文件输出、删除和独立哈希。原有 Chromium/Firefox DataChannel、文件 SHA-256 与同页恢复继续运行。**尚未完成跨刷新两端 UI 全链路 WebRTC E2E、移动真机、多浏览器存储兼容性、持久化配额异常/多标签碰撞以及真实跨运营商 NAT 测试**，不能宣传稳定可靠的跨页续传或正式发布。
