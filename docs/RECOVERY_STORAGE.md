# Zeydrop 浏览器本地断点（实验功能）

## 范围与用户操作

接收文件前主动选择“在本机保存断点”，数据仅写入该浏览器、该站点 Origin Private File System（OPFS）；不开启时沿用原来的 showSaveFilePicker/内存回退。中断后若刷新或关闭页面，双方需要新建邀请、重新建立非 relay WebRTC 路径、核对 DTLS 安全码。**发送者重新选择原文件**；接收者从收到的新邀请中主动确认匹配的本机断点，不能只凭名称自动恢复。恢复前本地读取并哈希检查点前缀，再由发送方对重新选择的文件计算同一偏移的 SHA-256；一致后才发送余下字节。全部文件必须再经过完整 SHA-256 才显示成功。

## 落盘边界及隐私

- 专用 Worker 用 FileSystemSyncAccessHandle 写入 OPFS（HTTPS 或 localhost），按约 1 MiB 更新持久化检查点；数据 flush **先于** JSON 清单的提交。崩溃可丢失最近不足 1 MiB 的进度，不能将未提交尾部当作有效内容，重新打开时必须截断到已保存 offset 并重新流式哈希。
- 最多接受 20 条正常/损坏的本机断点记录，保留期限 24 小时；**清理在再次打开网站或站点运行期间检查存储时执行，关闭所有标签后不会在后台自动计时清理**。损坏的元数据会作为可删除记录显示；超期孤立文件在确认未被使用后清理。用户可以在工作台“管理本机暂存文件”中手动删除或重新取得已完成且 SHA-256 校验通过的文件。完成文件也只在本机，用户点击保存后可删除副本。
- **点击“保存”不会立即删除本机 OPFS 副本**，因为下载未开始就删除源文件可能使浏览器取消下载；请在确认下载到系统目录后主动用“管理本机暂存文件”删除，或下次进入页面时按过期规则清理。Blob URL 在页面退出时释放。
- 本机暂存可能占用大量存储，受浏览器配额、隐私模式、清站点数据、OS 空间及存储驱逐影响，无法保证永远可恢复。站点同源脚本可以读取这些文件；不要在共享电脑上保留敏感内容。**文件数据、名称、哈希、偏移不进入 WSS 信令，也不上传服务器。**
- 界面上的匹配只是候选选择；不是授权或完整性凭证。使用非 relay selected ICE pair、双方重新人工核对安全码、用户接收确认、双方 prefix hash 和最终全量 hash 五层约束。失配不合并，要求重新传输或手动删除损坏的断点。
- OPFS 使用中的 exclusive lock 避免同一文件被多个 Writer 并发修改；第二标签页无法同时恢复同一个断点，应关闭占用标签页后重试。Worker 传回的 QuotaExceededError / NotAllowedError 需保留原始错误类型，以便客户端显示明确的存储/权限失败原因。硬件测试前不能保证 Safari/iOS 持久化和下载语义；浏览器不支持 Worker 同步访问句柄时不展示实验模式。
- 关闭浏览器不会保留发送方 File 句柄，也不会在服务端保存可恢复的会话 token。服务器重启后的信令身份和房间失效，必须创建新邀请；没有 TURN 文件中转。

## 跨刷新发送清单（2026-11-06 新增，CI52通过）

“跨刷新保留待发清单”独立于接收端OPFS断点。用户先主动勾选本机存储同意，再选择文件；浏览器按256 KiB增量计算完整SHA-256，仅在同源localStorage保存文件名、大小、MIME、修改时间、哈希及随机条目标识。**不保存File、文件句柄或文件正文，也不保存邀请、设备身份或安全码**。最多100项、128 KiB记录、固定24小时期限；成功发送/修改清单不延长期限。文件名与哈希仍可能敏感，共享设备请主动删除；过期清理需要再次访问存储，不保证关闭网站后的后台删除。

刷新后清单不会自动发送。双方新邀请、重新核对安全码，发送者点击“重新选择全部原文件”；完整内容哈希与名称/大小/MIME匹配后按原顺序绑定当前页File，再手动点击发送。重选顺序可以不同；修改时间仅作记录，不作为内容身份凭证。每个文件仍须接收方同意，接收端选择原OPFS断点时仍独立执行前缀校验。只有收到最终长度/完整哈希/保存成功的complete，且实际发送哈希与清单一致，才逐项移除；进度100%、拒绝、取消和失败均不会删掉未完成清单。

Web Locks独占提交及revision比较防止多个标签覆盖；哈希在锁外分块运行，提交前锁内再检查。另一标签页变更会撤销本页原件绑定，必须重选。损坏、过期、配额不足、取消校验都有明确失败，不退回服务器保存；无Web Locks或安全随机能力时不显示本机发送清单，普通当页发送仍可用。清单删除不隐式取消已授权的当前传输。

同页发送失败引用最多30项、15分钟，用户可以手动“重新发送”，生成新transfer ID并重新征求接收同意。失败/拒绝暂停并保留后续队列，用户选择继续或清空；断线释放这些失败重试引用，原有120秒同页恢复规则保留。原Blob待保存的ready-next屏障保持，不能借重试或继续绕过。

Firefox验收修复：浏览器可能恢复动态勾选状态（[Mozilla说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/checkbox)）。本机发送清单同意框禁用表单自动恢复，页面初始化/退出及BFCache返回时重置，文件选择控件清空；浏览器恢复表单不等于新的用户存储授权。CI50保留了Firefox真实失败，后续必须以未放宽断言的新CI验证。

最终CI52验证三引擎发送清单完整通过、Firefox errors=[]；许可/BFCache及锁callback修复均保持原错误和严格最终断言。完整范围见TEST_REPORT_20261107，实机存储验收仍开放。
