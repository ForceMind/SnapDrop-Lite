## 问题与实现

生产ReceiveDialog原先为每个已完成暂存文件立即创建Blob URL，关闭后增加一个pagehide监听器，直到离开页面才撤销。连续保存累积URL及监听器；即使只关闭窗口也保留下载地址。另外，共用保存链接的close监听器在浏览器默认下载动作之前同步切到下一文件，可能覆盖href/download。

本轮只改接收UI，不改服务器、授权、ICE、传输协议、SHA或OPFS数据。暂存文件只在保存点击创建URL；每个接收控制器最多20个已点击地址，满时阻止当前下载并提示等待，绝不提前撤销旧地址腾位。每个地址60秒宽限后释放，一次pagehide监听器统一清理地址/计时器；关闭未保存文件不创建URL，不删除本机副本。暂存管理面板原有独立20项上限不变，两个入口合计最多40项暂存下载地址。

保存点击capture先于基础Dialog关闭处理，浏览器默认下载动作后用下一计时任务关闭/推进队列；同文件重复点击被阻止，延迟关闭绑定原active引用。普通非持久文件保留原有1秒URL宽限及sink release。60秒只用于启动下载，不是下载完成确认，不保证任意浏览器/硬件后台冻结后的超长下载；本机原件仍可管理/重试。file-saved仍表示保存交互已关闭，并非浏览器写盘成功回执。
