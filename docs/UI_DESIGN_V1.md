## 1. 产品定位

**Direct by design.** 服务端只处理配对、信令和站点资源，绝不保存或转发文件正文。WebRTC DataChannel 是唯一文件正文传输通道，STUN 用于获得可穿透的连接候选（STUN 不承载文件正文），不配置 TURN；当非中继路径不通时，展示失败与可行建议，而非暗中中转。

目标用户：需要在 Windows/macOS/Android/iOS、家庭宽带与移动网络之间交换文件的普通用户。优先 Web/PWA；不要求登录，不引入云盘、文件过期存储或收费流量。

## 4. 交互细节

### 创建邀请
1. 生成 16 字节的加密随机数，转换为 32 个十六进制字符（128 bit）。
2. 将 room ID 放入分享 URL 的 `room` 参数；不使用可猜测的 6 位公开码作为默认公网方案。
3. 异步加入房间；即使 WebSocket 此时尚未建立，也先保存在 `ServerConnection._desiredRoomId`，待 WS open 再发送。
4. 服务端成功确认 `room-joined` 才显示“房间已就绪”；失败则显示 `room-error`。
5. 链接通过 Clipboard API 复制；若无权限，则选中文本供手动复制。

### 加入房间
1. 接受邀请 URL 或 room ID。
2. 验证输入，更新地址栏 `?room=<id>`，发送 `join-room`。
3. 服务端验证高熵 room ID（公网模式）、房间最多两人、每连接限频，并返回确认消息。
4. WS 断线自动重连并重新加入 `_desiredRoomId`。

### 发现与选择设备
- 已有的 PeerUI 保持文件选择、拖拽、粘贴、右键/长按发文字入口。
- 设备数通过已有事件更新。
- 信令在线 **不代表** P2P 文件路径已经成功建立；目前上方显示的是“信令服务在线”，后续 M2 再增加 ICE candidate 路径核验。

## 5. 本轮交付的代码范围（V0.1）

- `client/index.html`：全新首页语义结构，保留现有 Dialog 与脚本挂载节点。
- `client/styles.css`：品牌中性、响应式新视觉系统。
- `client/scripts/ui.js`：邀请、粘贴加入、房间状态、设备数量、信令状态。
- `client/scripts/network.js`：排队房间加入、WS 断线后恢复房间、标签页独立身份；增加“先发文件请求、接收方授权、再发送字节”握手及文件请求 ID 关联。
- `client/config.js`：默认 STUN 开启（无 TURN）。
- `server/index.js`：公网初始隔离、严格信令转发、房间限制、代理可信边界。
- `deploy.sh`：修复 STUN 默认配置与公网模式提示，新增 HTTP 暂不可直接公网发布警告。
- `tests/signaling.test.cjs`：信令权限和邀请流程的 Node 无依赖冒烟用例。

## 6. 必须继续实现，禁止虚假宣布完成
