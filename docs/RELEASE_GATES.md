# Zeydrop 正式发布门槛（Direct-only）

此文件是**发布验收事实清单**，不是对当前版本“已完成”的宣称。发布由用户决定；仓库 `main`、正式服务器与域名不自动修改。请勿将同一 GitHub Runner 上的浏览器 UDP 传输当成跨运营商 NAT 穿透成功。

- [x] 双人高熵邀请、已配对席位锁定/过期处理、WSS Origin 及信令白名单、文件正文不经 WebSocket 的协议约束。
- [x] Chromium 与 Firefox 双向 DataChannel、接收授权/文件 SHA-256、失败拒绝、同页短时续传与实验性 OPFS 跨刷新续传。
- [x] Node 自动化测试、构建/依赖审计、TLS 自签名临时 Nginx 反向代理集成、WebKit **UI smoke**（不是实际 Safari 文件互传）。
- [x] 脱敏连接诊断与本地流式 SHA-256 证据核验工具。
- [ ] **Chromium ↔ Linux WebKit 文件互传**：CI #40/#41 中 SDP/安全码存在，2/2 host ICE candidates 被服务端转发，但 ICE 维持 `new`、选中路径为空，文件未传输；即便补充标准 selected-pair API / 可空 ICE 字段处理也尚未恢复。后续须复现/明确支持范围；不能写“iOS Safari 已支持”。
- [x] CI #41 成功生成、校验 SHA-256 的未发布开发包；下一提交还将重复打包核验一致性。**未执行独立源码秘密扫描/签名**，也不构成正式发布或实际部署。
- [ ] 在一台独立测试服务器上实际安装、执行 TLS 证书与 systemd 重启/回滚演练。

## 必须由真实环境完成的验收（目前均未取得证据）

1. **两台真实网络设备**：家庭宽带↔家庭宽带、家庭↔4G/5G、两个移动运营商，至少各取一组成功/失败样本。分别记录发送者/接收者的实际 selected non-relay ICE pair，若无法选中则记录失败，不启用 TURN/DERP/WS 文件代理。
2. **复杂 NAT**：IPv4/IPv6 双栈、NAT64（有该网络时）、CGNAT/严格 NAT、防火墙/UDP 阻断、Wi-Fi↔蜂窝切换、后台冻结，记录连接失败原因与重试次数。不得给出无样本支撑的“公网成功率”。
3. **设备/浏览器**：Windows Chrome/Edge/Firefox、macOS Chrome/Safari、Android Chrome、iOS Safari；真实文件选择/保存权限、中文文件名、0B/小文件、多文件/图片/文本、100 MiB 和能力足够时 1 GiB、暂停/取消/拒绝、PWA 升级与恢复。
4. **服务器流量**：在真实端点 100 MiB/1 GiB 文件传输期间，从服务端实际观察 HTTPS 静态、WS 心跳/SDP/ICE 和 STUN 的区别；验证服务器**不接收或转发文件正文**，不能宣称服务端总流量为零。
5. **独立测试主机**：真实域名证书和续期、TLS/WSS、安全头、Node/systemd 非特权进程、开机重启、日志脱敏、旧 Snapdrop 迁移、失败恢复和回滚。不得在未经用户授权的生产主机试验。
6. **验收记录**：双方诊断（每端最新记录必须是选中的非 relay 路径）、两端独立 SHA-256 文件结果、测试版本/设备/网络、失败样本、服务器流量证据。用 `node scripts/field-verify.cjs --help` 获取本地核验命令；该工具无法独立证明真实公网拓扑或运营商。

## 发布决策

上述未验证项补齐且没有阻断缺陷后，再讨论将 PR #2 从 Draft 转为 Ready、合并 `main`、部署受控正式环境、创建 Release。不可在同机测试通过时自动升级为稳定版。**仓库原地更名为 Zeydrop 最后由用户手动执行。** 只做网页的版本不具备原生 PCP/NAT-PMP/UPnP 能力；M5 原生增强属于可选下一代路线，并非 Web MVP 的发布前提。局域网自动发现不得以“相同公网 IP/CGNAT 前缀”冒充可信邻居，当前安全配对通过主动邀请/二维码完成。
