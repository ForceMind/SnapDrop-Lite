# 2026-11-07 界面对比度审查

本轮依据 CI54 桌面/手机截图和实际 `client/styles.css` 追查颜色来源，修复了可从样式确认的对比度问题。下面是 CSS 颜色计算和有限的静态检查，**不是完整 WCAG 符合声明，也不是屏幕阅读器、真机触控或 Safari 无障碍验收**。样式修改后的实际浏览器/深色界面检查仍须结合后续 CI 和截图；不得沿用修改前的截图作为修复通过证据。

## 依据与计算方法

- W3C [SC 1.4.3 Contrast (Minimum)](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)：普通文字最低 4.5:1；足够大的文字可用 3:1。这里的 10–13px 提示文字按普通文字处理，不能因为加粗就使用较低阈值。占位文字也在范围内；不操作的 disabled 控件和纯装饰另有例外。
- W3C [SC 1.4.11 Non-text Contrast](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)：作者提供、用于辨别控件状态的视觉信息需对相邻颜色达到 3:1，包括可见焦点指示。本文的焦点线位于控件外侧，比较其所在面板背景；不要求所有装饰性边框均为 3:1。
- 采用 W3C 的 [relative luminance](https://www.w3.org/TR/WCAG22/#dfn-relative-luminance) 与 [contrast ratio](https://www.w3.org/TR/WCAG22/#dfn-contrast-ratio) 定义。不是从抗锯齿截图像素反推文字颜色。

每个 sRGB 通道先归一化到 0–1；当通道值不大于 0.04045 时除以 12.92，否则取 `((c + 0.055) / 1.055)^2.4`。相对亮度为 `0.2126R + 0.7152G + 0.0722B`，对比度为 `(较亮亮度 + 0.05) / (较暗亮度 + 0.05)`。只有已知不透明底色时，才对元素 opacity 作 `alpha * 前景 + (1 - alpha) * 背景` 的 sRGB 合成；计算中不先把通道取整。表格仅为显示而保留六位小数，是否达标使用未取整值判断。

## 实际修复

继续使用原有绿色与薄荷色体系，未改布局、传输状态、授权或交互流程：

- 弱文字统一使用 `--muted`：浅色 `#4d6657`、深色 `#a9c3b0`，替换分散的浅灰绿色，保留标题与主要按钮的视觉层级。
- 增加明确的 `--surface` / `--surface-muted` 两套主题颜色。此前未定义 `--surface`，使深色本机暂存面板退回白底，却继承近白色文字；现在深色面板为 `#192922`，正文与可操作按钮继承 `#ebf7eb`。
- 邀请输入框显式设置 placeholder 颜色及 `opacity: 1`，避免依赖各浏览器不同的占位字透明度。
- 删除说明文字不必要的低 opacity，使用可读的主题弱文字色；关于页小字由 0.7/0.5 提升到 0.9。
- 焦点线统一由 `--focus-ring` 控制：浅色 `#337b5a`，深色保留 `#6dbd92`；仍为 3px 线宽和 4px 外偏移。未取消原有键盘焦点。

## 验证范围与剩余验收

- 对修改后的实际 CSS 执行 esbuild 内存解析，无语法错误；通过一次性数值计算复核上述颜色。不新增复述样式常量的颜色单元测试。
- 页脚、品牌副标题和介绍区共用新的弱文字色，但其背后存在渐变、纹理、阴影；本文**没有猜测这些区域某一点的最终背景色，也没有给它们编造精确截图对比度**。需要后续实际浅色/深色桌面与手机截图检查。关于页仅计算动画展开后固定绿底，不覆盖动画中间帧。
- 建议浏览器回归在深色下展开本机暂存面板，查看空态、至少一条记录、启用的“删除”及“验证并准备保存”控件，核实 `#192922` 表面和继承文字；仅检查首页的深色截图不会覆盖此缺陷。组件截图应避免真实文件名、邀请及安全码。
- 建议核查浅色/深色 placeholder 的 computed opacity、键盘 focus-visible 的线色和宽度、接收确认弹窗、关于页以及 390px 布局，并复查 hover/焦点叠层后的实际显示。此文不宣称这些浏览器步骤已经执行。
- 真实屏幕阅读器、操作系统高对比度/强制颜色、放大与文字间距、触控、真实 Safari/iOS、真实 PWA 生命周期等外部无障碍验收仍然开放，按原发布门槛执行。
